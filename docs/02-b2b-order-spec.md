# 02. B2B 발주 시스템 기획 확정본

2026-08-17 기획 확정, 이후 실무 피드백으로 두 차례 개편(부가세 별도 / 입금확인 분리).
원본 기획 아티팩트: https://claude.ai/code/artifact/e4cd24a2-b85c-4ad9-93f2-83d7c6ca40b6

## 1. 전제

주류 B2B 라 **온라인 직접 결제를 하지 않는다.** 발주는 "주문서 접수"이고
대금은 계좌이체로 받는다. 회원은 **사업자만** 가입할 수 있다.

## 2. 확정 정책 (변경 시 반드시 사용자 확인)

| 항목 | 확정 내용 |
| --- | --- |
| 결제 | 없음. 계좌이체 — 하나은행 218-910408-18407 (골드럭와인) |
| 가입 자격 | 사업자만. 국세청 API 자동 검증 + **관리자 수동 승인** |
| 국세청 판정 | `b_stt_cd === '01'`(계속사업자)만 정상. 휴업(02)·폐업(03)은 실패 처리 |
| 가격 열람 | **승인된 거래처와 관리자만**. 비로그인·미승인에겐 공급가가 보이지 않는다 |
| 최소 발주 | **6병** (`order_settings.min_bottles`) |

| 입금 기한 | 3일 (`order_settings.deposit_days`) |

| 세금계산서 | **홈택스 반자동** — 대장 CSV 다운로드 + `orders.invoiced_at` 기록. 팝빌(건당 200원)은 비용 때문에 채택 안 함 |
| 알림 | 1단계 **이메일**(Gmail SMTP). 2단계 카카오 알림톡은 **보류** |
| 재고 | 발주와 **동시 차감**, 취소 시 **자동 복구** |

## 3. 상태 흐름 (2026-08-19 개편)

```
접수(awaiting_deposit) → 배송중(shipping) → 완료(done)
                      ↘ 취소(canceled)
```

**입금은 상태가 아니라 별도 플래그(`orders.paid_at`)** 입니다.
수입사 실무에서 "배송 먼저, 입금 나중"이 훨씬 많아 입금확인을 흐름에서 분리했습니다.

- `paid` 상태값은 레거시로 남아 있고 라벨은 `접수(입금)`. 신규 흐름에선 쓰지 않는다.
- 미입금 판정: `src/api/orders.ts` 의 `isUnpaid()` — `!paid_at && status !== 'canceled'`.
- 거래처가 직접 할 수 있는 전이는 **접수 → 취소** 하나뿐 (`orders_guard` 트리거가 강제).

## 4. 가격 계산 규칙 (단일 지점)

서버 `submit_order` RPC 가 최종 권위입니다. 클라이언트 값은 표시용이며 위조해도 반영되지 않습니다.

```
병 단가(공급가) = floor( coalesce(sale_price, price) × (1 - 거래처 할인율/100) )
품목 금액       = 병 단가 × 수량
공급가 합계     = Σ 품목 금액
부가세          = Σ round(품목 금액 × 0.1)     ← 행 단위 반올림
입금액          = 공급가 합계 + 부가세
subtotal        = 할인 전 합계, discount_amount = subtotal - 공급가 합계
```

클라이언트 측 동일 규칙 구현: `src/api/pricing.ts` 의 `effectiveUnitPrice()`, `vatOf()`.
**할인 규칙을 바꾼다면 이 두 곳(RPC + pricing.ts)을 함께 고쳐야 합니다.**

발주 시점의 단가·상품명은 `order_items` 에 **스냅샷**으로 저장되므로 이후 와인 정보가
바뀌거나 삭제돼도 과거 발주서는 변하지 않습니다.

## 5. 발주 생성 시 서버 검증 (`submit_order`)

1. 승인된 거래처인가
2. 장바구니 품목 중 `orderable = true`, `is_visible`, `sold_out = false` 인 것만 집계
3. 재고 부족(`stock is not null and stock < qty`) 시 예외 — 어떤 품목이 몇 병 부족한지 메시지에 포함
4. 품목 0개 / 최소 병수 미달 시 예외
5. `orders` + `order_items` 생성, 재고 차감, 장바구니 비우기

관리자 대리 발주(`admin_submit_order`)는 재고가 부족해도 진행하되 `greatest(stock - qty, 0)`
으로 음수를 막습니다. 관리자 재량을 막지 않기 위한 의도된 차이입니다.

## 6. 사용자 여정

### 거래처

1. `/order/login` → `/order/signup` 1단계(이메일·비밀번호) → 2단계(사업자 정보)
   - 사업자번호 입력 시 국세청 자동 조회(onBlur + 제출 시 재검증)
   - 사업자등록증 업로드 → `partner-docs` **private** 버킷
   - 이용약관·개인정보·성인 확약 동의(전체 동의 체크 제공) → `terms_agreed_at`
2. 관리자 승인 대기 → 승인 메일 수신
3. `/order` 발주하기 — 카탈로그에서 담기, 검색·타입 필터, 재고 상한 표시
4. `/order/checkout` → `/order/complete` (계좌·입금 기한·최소 병수 안내)
5. `/order/history` 발주 내역 — 상태 확인, 접수 건 취소, 거래명세표 인쇄
6. `/order/account` 내 정보 — 담당자·배송지·세금계산서 수신 메일 수정

### 관리자

1. `/admin` **대시보드** — 접수/배송중/미입금/이번 달 액션 카드, 대기 목록(승인대기·계산서
   미발행·재고 부족·새 문의), 진행 중 발주, 차트 3종
2. **거래처** 탭 — 가입 승인/반려, 할인율·메모, 서류 열람(signed URL), 수기 거래처 생성
3. **발주** 탭 — 상태 변경, 입금 확인, 대리 발주, 발주 수정(수량·단가·품목 추가), 발주 복사,
   메모 편집, 거래명세표 출력, 세금계산서 대장 CSV, 발주 내역 CSV, 행 선택 일괄 처리
4. **와인** 탭 — 공급가·할인가, `발주 가능` 토글, 재고 입력
5. **설정** 탭 — 최소 병수·입금 기한·계좌·공지·공급자 정보

## 7. 알림 이메일

Supabase **Database Webhook** 이 `partners`/`orders` 의 INSERT·UPDATE 를 `/api/notify` 로
보내면 서버가 발송합니다. 클라이언트는 발송에 관여하지 않으므로 위조가 불가능합니다.

- 발송 경로: **Gmail SMTP 우선**, 미설정 시 Resend 폴백.
- Resend 를 버린 이유: 도메인 인증이 불가해 테스트 모드에서 계정 소유자 메일로만 발송됐다.
- 거래처 발송 메일에는 `goldluckwine@gmail.com` 을 **CC** 로 넣어 발송 이력을 남긴다.
